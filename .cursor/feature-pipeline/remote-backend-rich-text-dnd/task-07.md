# Task 07: Contract: switch storage to PGlite and Postgres

## Context
The AI Work Board (repo root `/Users/neazmahmood/Desktop/projects/practice/ai-work-board`) now runs its whole domain core on the async `ctx.adb` (`AsyncDb`), still backed by SQLite. This **contract** step replaces SQLite:
- Hosted mode stores data in Postgres (`postgres` driver, connection URL).
- Local mode stores it in PGlite (`@electric-sql/pglite`, already installed), in a directory under the data dir.
- Tests use in-memory PGlite.

One backend instance is the only writer, and every write transaction is serialized by the in-process write mutex. Existing SQLite data is deliberately not migrated.

## Do
- `src/server/db.ts`:
  - Becomes the async interface only: rename `AsyncDb` to `Db` (`get`/`all`/`run`/`tx`, as now) and delete the sync interface and `openSqlite`.
  - Add a helper that rewrites `?` placeholders to `$1..$n` (domain SQL has no `?` inside string literals) and use it in both adapters.
- `src/server/db-pglite.ts` (new): `openPglite(dir?: string): Promise<Db & { close(): Promise<void> }>`. `dir` undefined means in-memory.
  - PGlite has a single connection, so **every** statement outside a transaction also goes through the write mutex.
  - `tx` uses `AsyncLocalStorage` to join nested calls and runs its statements on the PGlite transaction handle.
- `src/server/db-postgres.ts` (new): `openPostgres(url: string, opts?: { schema?: string }): Promise<Db & { close(): Promise<void> }>` on the `postgres` driver.
  - `tx` takes the write mutex and uses `sql.begin`.
  - Nested calls join via `AsyncLocalStorage`.
  - Reads outside a transaction use the pool.
  - If `schema` is given, create it if missing and set `search_path` to it on every connection.
- `src/server/writeMutex.ts`: keep as is; both adapters use it.
- `src/server/migrations.ts`:
  - Replace the migration list with a fresh Postgres baseline with the same tables and columns (`app_meta`, `schema_version`, `projects`, `tickets`, `actors`, `activity`, `comments`, blockers, features, and anything else the current list creates).
  - Use `INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` for ids, keep TEXT ISO timestamps and the TEXT JSON payload, keep the CHECK constraints and `ON DELETE CASCADE`, and replace `COLLATE NOCASE` uniqueness with a unique index on `(project_id, lower(name))`.
  - `migrate(db)` becomes async.
- `src/domain/`:
  - Rename `ctx.adb` to `ctx.db` everywhere (the `Ctx` field is `db: Db`).
  - Search with `LIKE` becomes `ILIKE`.
  - Fix any remaining SQLite-only SQL. Check `RETURNING`, counts (`::int`), booleans, `ON CONFLICT`, and string functions.
- `src/server/app.ts`:
  - `AppOptions` drops nothing, and gains `database?: { kind: "pglite"; dir?: string } | { kind: "postgres"; url: string; schema?: string }`.
  - Default: `{ kind: "pglite", dir: path.join(dataDir, "pgdata") }`.
  - `close()` closes the database.
  - Never read or delete an existing `board.db`.
- `test/helpers.ts`:
  - `makeTestApp` uses in-memory PGlite (`{ kind: "pglite" }`).
  - When `process.env.TEST_DATABASE_URL` is set, it uses `{ kind: "postgres", url, schema: "awb_test_<random>" }` and drops that schema in `close()`.
- `test/skeleton.test.ts`: update the migration and table assertions for the Postgres baseline.
- `test/async-db.test.ts`: rewrite against PGlite. Delete the SQLite-specific cases, and keep the transaction, rollback, nesting and serialization cases.
- `test/concurrency.test.ts` (new), through `testApp.request` with `Promise.all`:
  - 10 concurrent `POST /api/projects/:key/claim` calls, as different Actors, against 5 eligible To Do Tickets → exactly 5 distinct Tickets claimed and 5 `{ ticket: null }` results.
  - 10 concurrent moves within one Column → the Ranks in that Column are exactly `0..n-1` afterwards.
- `scripts/e2e-server.ts`: works unchanged with the default PGlite in its temp data dir; update it if needed.
- Remove `better-sqlite3` and `@types/better-sqlite3` (`pnpm remove better-sqlite3 @types/better-sqlite3`), and the `allowBuilds: better-sqlite3` entry in `pnpm-workspace.yaml`.
